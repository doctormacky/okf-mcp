# Discover Existing Business Knowledge

Use this guide before proposing any Business change.

## Inventory

1. Check the runtime and Bundle:

   ```bash
   command -v okf
   okf --version
   okf --root <bundle-root> --strict-links validate
   ```

2. Read the reserved indexes relevant to the requested artifact, including
   `business/datasets/index.md`, `business/relationships/index.md`,
   `business/terms/index.md`, `metrics/index.md`, `policies/index.md`, and
   `queries/index.md` when present.
3. Search with one or two atomic business terms. Generic lexical search requires
   every term, so do not pass a complete natural-language request.
4. Read full matching Concepts, their physical Table Concepts, declared
   relationships, and `observations/current.md`.

## Match Existing Meaning

Update instead of create when any of these apply:

| Artifact | Existing match |
| --- | --- |
| Dataset | same `semantic.physical_table` |
| Relationship | same dataset endpoints or physical relationship |
| Term | same business meaning or physical binding |
| Metric | same business definition, base grain, and measure |
| Policy | same rule and physical scope |
| Saved Query | same business question and output grain |

Paths and titles alone do not establish identity. Record update/create decisions
in the proposal so the user can review them.

## Physical Evidence

Table Concepts generated by dbexplain expose:

- table comment in `description`;
- column name, datatype, key flags, and comment in the Schema body;
- exact table/column SQL bindings in `dbexplain.sql_binding`;
- declared JOIN bindings in physical Relationship Concepts.

Use table and column comments as the primary physical evidence for drafting
Business names, descriptions, field synonyms, time roles, and explicit enum
codes. Comments do not prove an ambiguous business definition or undeclared JOIN.

If current metadata is necessary and dbexplain is available, use bounded,
no-sample discovery:

```bash
dbexplain collect --label <label> --tables
dbexplain collect --label <label> --table <table> --json
```

The table list includes table comments; targeted JSON includes table and column
comments, types, keys, indexes, and foreign keys. Do not scan the live database
when the Bundle already contains sufficient current facts.

## Proposal Gate

Before asking for approval, identify:

- exact existing files to update and missing files to create;
- evidence for each proposed business statement;
- definitions that only the user can decide;
- whether SQL execution is required for a Saved Query or SQL expression.

Do not write while resolving clarification. Approval applies only to the proposal
shown; revise and re-confirm if its meaning or file set changes.
